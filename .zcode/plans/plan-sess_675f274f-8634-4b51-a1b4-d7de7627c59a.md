# 玄穹文枢生产级全链路重构计划

## 结论与实施原则

当前工作树已经具备 TaskRuntime、任务事件回放、质量门、长章 checkpoint、候选版本和连续性账本等骨架，但仍存在三个必须最先关闭的 P0 一致性缺口：

1. `TaskRuntime` 只有 claim/stale 使用条件更新；普通进度和终态写入没有 `attempt + lease_generation` CAS，旧 worker 仍可能写入新 attempt。
2. 正文会先标记 `successful`，账本再分段提交；异步定稿还可能基于旧版本继续更新账本，形成“选中版本 B、账本来自版本 A”的半定稿。
3. 正文编辑直接覆盖既有 `ChapterVersion.content`，章节、蓝图、大纲和快照缺少正式 revision/content hash，并发编辑会静默覆盖历史。

实施采用用户目标中已经给出的默认决策，不再另设平行架构：

- TaskRuntime 是后台任务唯一持久化状态真相源，内存字典只保留本进程协作句柄。
- 创作资产采用追加式 revision；旧字段保留并双读兼容，不做破坏性迁移。
- 正文确认与完整定稿分离：`candidate_ready → finalizing → finalized`；外部副作用走 outbox，未收敛时只显示“正文已确认、账本同步中”。
- 所有异步任务冻结输入 revision/hash、配置、Prompt、上下文和成本预算。
- 每项修复都先有 characterization test，再实现，再临时破坏关键条件确认测试失败，恢复后运行定向及全量门禁。
- 全程保留当前大量未提交成果，不 reset、不批量覆盖、不删除旧模型或旧 API；不改旧报告来制造完成。

## 批次 0：冻结证据和建立机器可读审计台账

### 0.1 建立审计资产

新增独立的审计目录，例如 `audit/production-readiness/`：

- `defects.yaml`：完整登记 13 个一级域、97 个叶子节点，字段至少包含 `id/domain/severity/location/status/reproduction/root_cause/user_impact/dependencies/fix/tests/negative_test/evidence/acceptance`。
- `baseline.json`：记录 Git commit、dirty 文件清单摘要、OpenAPI hash、数据库 schema revision、前后端测试数量与命令。
- `evidence/`：保存测试输出、HTTP/SSE 样本、数据库断言、正文/导出 checksum；敏感正文和 Provider 配置只保存脱敏摘要或 hash。
- 状态只允许 `CONFIRMED`、`IMPLEMENTED_UNVERIFIED`、`TESTED`、`REAL_VERIFIED`；无真实证据不得提升等级。

### 0.2 重新获得基线

- 后端严格执行工作区规定命令：`cd backend; .\.venv\Scripts\python.exe -m pytest -q`。
- 前端执行 `npm run type-check`、`npm run test:run`、`npm run build-only`。
- 单独记录当前失败，不以历史 `401/401`、`127/127` 或 `.pytest_cache` 作为证据。
- 导出当前 OpenAPI、TaskRuntime SSE envelope、典型项目/章节/候选版本/导出 manifest 的脱敏样本。
- 为当前确认的 P0 添加失败 characterization tests，首批覆盖：旧 worker 迟到终态、生成后自动选择最长候选、编辑覆盖原版本、异步定稿版本串线、ProjectMemory 丢失更新、重复定稿重复快照。

## 批次 1：TaskRuntime 成为唯一、可代际隔离的运行时

### 1.1 追加任务协议字段

在 `backend/app/models/task_runtime.py`、schema 和追加式 Alembic migration 中增加：

- `attempt`：每次 retry 递增，事件和产物明确归属 attempt。
- `lease_generation`：每次成功 claim/recover 原子递增。
- `input_hash`、`config_snapshot_id`、`artifact_ref`、`artifact_revision`。
- 结构化错误 JSON（兼容保留现有 `error_code/error_detail`）。
- 事件独立列 `attempt/lease_generation/channel/sequence/segment_index/content_hash`；旧 payload 投影继续兼容一个版本。

### 1.2 所有 worker 写入使用 CAS

重构 `TaskRuntimeService`：

- `claim` 只允许 queued/stale/过期 running，返回新的 `lease_generation`；同 owner 重入不得重复创建 started 事件。
- `heartbeat/update_progress/append_event/complete/fail/cancelled` 必须携带 `attempt + lease_owner + lease_generation`，通过条件 UPDATE 验证持有者。
- 旧 attempt 或旧租约写入返回结构化 conflict，不刷新 heartbeat、不写事件、不改变终态。
- retry 清理旧计时、租约和错误，递增 attempt，并让历史事件/产物保持可查询但不能覆盖当前投影。
- cancelling 增加统一收敛器：活 worker 协作取消；失联 worker 超时转 cancelled/stale reason，不无限停在 cancelling。
- 幂等键改成 `owner + task_type + scope + input_hash + asset_revision`；随机 run id 只作为 task identity，不参与业务去重。

### 1.3 统一业务 WorkerAdapter

新增通用 `TaskWorkerAdapter`，统一 claim、heartbeat、checkpoint、取消检查、错误分类、终态、恢复建议和指标。按顺序迁移：

1. 章节正文与长章分段。
2. 蓝图和章节纲。
3. 研究与文风画像/上传。
4. 导入。

`_BLUEPRINT_JOBS`、`_OUTLINE_JOBS`、`_RESEARCH_JOBS`、`_STYLE_*_JOBS`、`_IMPORT_JOBS` 只保留 asyncio task/取消句柄，不再用于 status 响应、去重或重启恢复。启动恢复改成 task type registry；执行规格不完整的任务转 stale 并给出人工动作，不盲目重跑。

### 1.4 唯一事件流

- 通用 TaskRuntime SSE 是规范入口；writer legacy SSE、updates API 和旧 start/status/cancel 变成兼容适配器。
- 服务端持久化后广播，Last-Event-ID 回放；正文、日志、进度、诊断、终态按 channel 分流。
- 前端统一 reducer 按 `task_id + attempt + sequence + content_hash` 去重，乱序缓存后按序应用；正文分片 checksum 不符立即失败并重新拉 artifact，禁止静默拼接。

### 1.5 批次 1 测试

- SQLite 文件库和 MySQL：双 worker 同时 claim、旧 worker 迟到 progress/success、retry attempt 隔离、取消与成功竞态、两个 stale sweeper、事件乱序/重复/断线回放。
- 各任务类型逐阶段杀 worker 后恢复；确认完成 checkpoint 不重做、外部调用不重复。
- 反向验证分别移除 lease generation、owner、attempt、sequence 条件，新增测试必须失败。

## 批次 2：版本化 canonical 创作资产

### 2.1 追加模型和迁移

新增稳定资产与 revision 表，不删除旧 JSON：

- `ProjectIntentRevision`、`LengthContract`。
- `BlueprintRevision`、`BookPlanRevision`、`VolumePlanRevision`、`StoryArcRevision`、`PlotThreadRevision`。
- `ChapterOutlineRevision`、`ScenePlanRevision`、`Scene`、`ChapterMissionSnapshot`。
- `GenerationInputSnapshot`、`ConfigSnapshot`、`PromptRevision`。
- 扩展 `ChapterVersion`：`parent_version_id/content_hash/status/input_snapshot_id/provenance`，正文版本改为不可变。

所有 revision 记录 `revision/base_revision/content_hash/created_by/created_at/source_task_id/status`。稳定实体 ID 与可变显示名称、章号、场景顺序分离。

### 2.2 增量回填与双读

- 从现有 Blueprint JSON、ChapterOutline metadata、scene list 和 ChapterVersion 生成 revision 1，保留原始 hash。
- 新写入只进入 canonical 表，并更新旧投影供兼容客户端读取；旧 API 双读一个兼容周期。
- 提供 checksum 比对脚本和 feature flag；关闭新写 flag 可恢复旧读路径，新表和旧数据均保留。
- 禁止删除、重编号或移动仍被正文、任务、账本引用的实体；改为归档或生成影响计划。

### 2.3 并发契约

- 蓝图、总纲、章节纲、场景和正文编辑请求统一携带 `base_revision` 或 `If-Match`。
- 条件更新失败返回 409、当前 revision 和字段级 diff；下游资产标 stale，不自动删除。
- 正文人工编辑总是创建新 `ChapterVersion`，不再原地覆盖旧候选；后台摘要和向量任务绑定新 version/content hash。
- `ChapterEvaluation` 绑定内容 hash、rubric revision、context revision、模型/Prompt；正文变化后自动 stale。

### 2.4 批次 2 测试

覆盖多标签并发编辑、后台生成与人工编辑竞态、同名/改名角色、章节插入/移动/删除、场景重排、历史版本续写和旧数据回填。反向移除 revision 条件或 content hash 后测试必须失败。

## 批次 3：灵感 → 蓝图 → 总纲/卷/弧 → 章节纲 → 场景的分层确认链

### 3.1 灵感与长度合同

- 用正式 schema 替换自由 Dict：题材、受众、禁区、人物、视角、结局、总字数、章数、章均范围、卷数和来源证据。
- 规则提取只生成候选；高风险约束和冲突必须进入待确认清单。
- 生成按钮绑定 intent revision/hash、ConfigSnapshot 和成本预估，确认后修改不影响已启动任务。

### 3.2 统一长篇结构

- `BookPlanRevision` 是唯一 canonical shape；旧平面阶段列表通过适配器转换，非法 fallback 只能保存 degraded draft。
- Volume 的章范围必须完整、无重叠；StoryArc/PlotThread 使用稳定 ID，定义范围、状态变化、揭示窗口和完成条件。
- 长篇任务拆成规模规划、卷骨架、弧线、章节骨架、依赖校验、用户确认，每阶段 checkpoint 后原子发布 artifact。

### 3.3 完整章节纲和正式 ScenePlan

- 前后端共用完整 ChapterOutline DTO，保存角色焦点、冲突、连续性、伏笔任务、信息增量、状态增量、结尾钩子、依赖和预算，不再只保存 title/summary。
- ScenePlan 持久化稳定 scene ID、order、goal/conflict/choice/turn/outcome/state_delta/bridge/hook/word_budget。
- AI 局部重写生成新 revision，并尊重锁定字段；正文只能引用已确认 scene revision/hash。
- 任一 blocker 或 stale mission 不得启动正文任务。

## 批次 4：正文生成、质量门和长章恢复

### 4.1 候选与生成语义

- 删除当前生成结束后按最长文本自动选择版本的行为；生成完成只到 `candidate_ready/waiting_for_confirm`。
- 短章默认一个候选；中长章由统一 RetryBudget 控制首稿、质量重试和局部修订，禁止 Provider、阶段和质量层叠乘法重试。
- 续写、改写、局部 patch 都创建有 parent/base hash 的新版本；索引只保留在旧 API 适配器，新接口只用稳定 version ID。

### 4.2 统一质量门

- 固化 `blocker/warning/degraded` DTO 和 rubric revision。
- 字数统一使用 `count_novel_words`，前后端共享中英混排测试向量。
- 元文本污染、角色硬事实冲突、重大世界规则、时间物理冲突、孤儿因果、major 伏笔错误回收为不可绕过 blocker。
- blocked 候选隔离保存；人工 override 只允许非硬 blocker，并记录用户、原因和版本 hash。
- 建立分题材人工标注集，节奏和审美阈值保持 warning，不用单一启发式阻断所有题材。

### 4.3 长章 artifact/checkpoint

- 大正文和分段不进入 TaskRuntime payload；任务只保存 artifact ref、offset、segment hash、计划 hash。
- 每段写入幂等，恢复时验证前段 hash 和 lease generation；不匹配立即 stale/fail closed。
- 验证真实 20k 章节在段 2 后断流、取消、杀进程、重启、续接，最终前后端 checksum 一致。

## 批次 5：硬事实账本与原子定稿

### 5.1 定稿会话和 outbox

新增 `FinalizationSession`、`DomainEvent`、`DomainEventOutbox`：

- 会话冻结 `chapter_id/version_id/content_hash/chapter_revision/memory_version/input_snapshot_id/commit_id`。
- 状态为 `prepared/finalizing/content_confirmed/ledger_committed/outbox_pending/finalized/failed/superseded`。
- 开始及每个阶段都重新校验当前选中版本与 hash；用户改选后旧会话转 superseded，禁止继续写账本。
- ProjectMemory 使用真正的 CAS 条件更新；失败重算或返回冲突，不允许普通 `version += 1` 静默覆盖。
- ChapterSnapshot 增加 version/content/commit/memory before-after 信息和唯一幂等键。

### 5.2 单一源事件与投影

- 角色、势力、时间线、因果、伏笔、线索、知识图谱统一来自 append-only domain events；现有表作为幂等投影。
- 结构化角色状态写入稳定 character ID、证据、置信度、来源 version 和幂等键；低置信度待确认，LLM 摘要不能覆盖硬事实。
- 正文回退或编辑使派生投影 stale，并可按 commit/version 重建；删除源事件使用修正/撤销事件，避免投影“复活”。

### 5.3 提交边界

- LLM 提取在事务外基于冻结快照计算。
- 一个短数据库事务确认正文、章节业务状态、ProjectMemory CAS、快照和全部数据库 domain events。
- 向量库、缓存和其它外部写入只由 outbox worker 执行，按 commit ID 幂等重试。
- outbox 未完成时 UI 显示“正文已确认、账本同步中”；所有必要投影及 outbox 收敛后才显示 finalized。

### 5.4 故障注入

在摘要、角色状态、时间线、因果、伏笔、线索、图谱、快照、事务提交、outbox 派发和向量写入每个步骤注入失败；断言无半定稿、重复副作用或 A/B 版本串线。重复定稿同一 hash 必须命中同一会话。

## 批次 6：Provider、配置、成本、研究与文风

- `ConfigSnapshot` 冻结 Provider、模型、参数、配置 revision；`PromptRevision` 的 cache key 强制含 revision/content hash，Prompt 缺失 fail closed。
- 统一 RetryBudget、TimeoutPolicy、阶段 reserved/actual token 和费用；超预算暂停并要求确认。
- 用户/Provider/模型建立跨 worker 并发令牌与项目背压。
- 研究结果版本化，保存 query、scope、来源 URL、抓取时间、可信度和配置快照；正文 ContextSnapshot 引用具体片段。
- 文风上传统一 txt/docx/epub 支持矩阵、大小/恶意 XML 检查、授权、保留期限和内容指纹；StyleProfileRevision 绑定项目和生成快照，避免跨项目串风格。
- 敏感字段 registry 对任务 payload、Prompt、日志、研究原文和正文预览统一脱敏并限制大小；正文外置 artifact，日志访问执行 RBAC。

## 批次 7：导入导出工程往返

- 定义版本化工程 manifest：schema version、checksums、资产列表、版本图、选中关系、评审、patch provenance、场景、研究、配置引用和账本源事件。
- 清楚区分阅读 TXT/DOCX/EPUB 与完整工程包；阅读版 UI 不宣称可完整回程。
- 导入执行 `解析 → staging project → 全量校验 → 原子发布`，使用业务幂等键；损坏、取消或重启不得在正式项目留下部分数据。
- 章节切分改为预览、置信度和人工确认；无标题、重复标题、200+ 章不自动正式提交。
- 空库 roundtrip 后比较资产数量、稳定 ID 映射、关系、版本图和所有 checksum；源事件必须保留，派生投影允许重建。

## 批次 8：前端统一工作流

- 建立全局 TaskRuntime store 和唯一事件 reducer；页面启动时调用 `listTasks(owner/project, active statuses)`，即使项目快照缺 task ID 也能恢复。
- 蓝图、章节纲、研究、文风和导入改用统一 SSE；轮询仅作兼容降级。
- 拆分 `WritingDesk.vue` 为 project context、chapter controller、task reducer、generation controller、finalization controller 和 modal controller，保留现有组件行为测试。
- 蓝图、卷、弧、章节、场景提供 revision compare、字段级编辑、冲突 diff 和下游 stale 提示；禁止章节编辑器删除后无条件重编号。
- 统一 `ErrorEnvelope → UIAction`，failed/stale/cancelled/conflict/superseded/outbox pending 都提供明确动作和诊断 ID。
- 长正文使用块缓冲/虚拟化；完成窄屏、键盘和 axe 可访问性验证。

## 批次 9：真实生产验收与发布门禁

### 自动门禁

每个批次先跑定向测试，再跑：

- 后端全量 pytest。
- 前端 type-check、Vitest、build-only。
- Alembic 000→最新、最新→前一版→最新，使用隔离库；SQLite 和 MySQL 运行关键 CAS、事务、唯一键测试。
- 密钥/隐私 canary 扫描 TaskRuntime、日志和 artifact metadata。

### 浏览器与真实环境门禁

建立 Playwright 黑盒流程并连续执行两轮：

1. 灵感 → 蓝图 → 总纲/卷/弧 → 章节纲 → 场景 → 正文候选 → 评审 → 定稿 → 导出。
2. 页面刷新、断网、SSE 重连、Last-Event-ID 回放和 checksum。
3. 真实 Provider 短章串行十次。
4. 真实入口连续生成并定稿 1—10 章。
5. 真实 20k 长章在断线、取消、进程重启后续接。
6. 双用户、双项目、双 worker，一成一败和一取消一成功。
7. 完整工程导出到空库再导入并重建投影。

任何跨用户/项目串线、取消复活、任务/资产伪终态、元文本污染、富字段丢失、分段错乱、major 伏笔错误回收、半定稿、部分导入伪成功、revision 静默覆盖或 SSE 正文缺失/重复都阻断发布。

## 实施组织与每批交付物

- 严格按 0→9 批次推进；前一批 P0 门禁未过，不在后一批堆叠兼容补丁。
- 每个批次都提交代码、追加式 migration、正向测试、反向失败证据、定向与全量结果，并更新机器台账；不改历史报告结论。
- 每完成一个可独立验证的切片就检查 Git diff，确保只包含本切片修改且没有覆盖现有未提交成果。
- 不自动 commit 或 push；最终交付提供改动文件、迁移说明、真实命令结果、未完成/外部阻塞项和 97 节点状态汇总。
