【2026-04-28 托管式深度优化计划】

目标：以“可运行、可验证、可交付”为准，持续推进玄穹文枢全量优化。先解决 P0 功能缺陷，再落地前端完全重构。

一、P0 必须立即修复

1. 前端测试红灯
   - 修复 chapterGeneration 阶段标签、状态归一化、批判摘要。
   - 修复 ChapterGenerating 批判摘要展示。
   - 修复 WritingDesk 终止失败/同步告警乱码。
   - 验收：npm run test:run 通过，npm run build 通过。

2. 章节生成字数不生效
   - 定位 writer.py / pipeline_orchestrator.py 中 preset longform 强制 3000 字的逻辑。
   - 改为尊重前端 target_word_count/min_word_count；如 preset 覆盖必须显式返回 warning。
   - 验收：请求 700/350 不再变成 3000/3000。

3. 生成任务卡住不可诊断
   - 为 generation_runtime 增加 stale 判断所需字段或前端统一派生。
   - 状态长时间不变时给出“疑似卡住/可取消/可重试”。
   - 验收：任务停留 generate_variants 超阈值时前端与 API 均能看到可解释状态。

4. 蓝图生成超时
   - 最小方案：前端超时保护 + 后端超时错误结构化。
   - 中期方案：蓝图生成任务化，返回 task_id，支持轮询/取消/降级草案。
   - 验收：用户不会在蓝图页无反馈等待 8 分钟。

5. 日志和用户可见乱码
   - 修复前端 hardcoded mojibake 字符串。
   - 确认日志文件实际编码，修正读取/输出路径。
   - 验收：UI 与日志管理页不出现可见乱码。
