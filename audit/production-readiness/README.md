# 批次 0：生产就绪机器可读审计台账

本目录只建立审计骨架，不表示系统已生产就绪，也不把历史报告或测试绿灯自动视为发布证据。

## 文件

- `defects.yaml`：13 个一级域、97 个叶子功能的状态台账。
- `baseline.template.json`：后续冻结提交、工作树、契约、数据库和测试结果时使用的空模板。
- `evidence/`：保存脱敏后的命令输出、HTTP/SSE 样本、数据库断言、checksum 和反向验证记录。

## 数量口径

- `declared_count: 97`：实施计划声明的目标数。
- `source_enumerated_count: 35`：`PRODUCTION_MASTER_OPTIMIZATION_PLAN.md` 总体逻辑树实际显式枚举的 A1—G5 数量。
- `enumerated_count: 97`：本台账依据总体逻辑树、五份分域生产计划和当前审计结论拆出的叶子记录数。
- `domain_count: 13`：本台账一级域数量。

原目标声明与原总计划显式枚举数不一致，故两者均如实记录；本台账的 97 项是批次 0 的审计细分口径，不声称原总计划逐字列出了 97 项。

## 状态规则

本批次只允许：

- `CONFIRMED`：已有静态或运行证据确认缺口存在。
- `IMPLEMENTED_UNVERIFIED`：存在实现骨架，但缺少该叶子节点要求的完整生产验收证据。

批次 0 不使用 `TESTED` 或更高状态。后续提升状态必须填写可复核的 `evidence`，且按节点完成正向测试、反向破坏验证和规定门禁。

## 证据规则

1. 证据文件应脱敏，不保存密钥、JWT、完整 Prompt、用户正文或 Provider 私密配置。
2. 每条证据至少关联节点 ID、命令/入口、时间、退出码或终态、关键断言和产物 hash。
3. 历史报告只能作为线索，不能单独提升状态。
4. `baseline.template.json` 是模板；未填字段必须保持 `null`、空数组或 `not_run`，不得填入推测结果。
